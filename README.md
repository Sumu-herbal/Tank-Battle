## 快速开始

### 启动服务器

```bash
cd tank-battle
npm install
npm start
```

服务器会显示本地和局域网访问地址：
```
🟢 坦克大战服务器已启动！
   本地访问: http://localhost:3000
   局域网访问: http://192.168.x.x:3000
```

### 加入游戏

1. **主机玩家**：浏览器打开 `http://localhost:3000`
2. **局域网玩家**：浏览器打开 `http://<主机IP>:3000`
3. 在主菜单输入服务器地址，点击 **⚔️ 加入战斗**

> 确保所有设备在同一局域网内，且服务器防火墙允许 3000 端口。

## 游戏规则说明

### 核心目标
- **消灭所有敌方坦克**，保护己方基地（地图底部的鹰标旗帜）
- 基地被摧毁则**游戏结束**
- 每波敌人全灭后进入下一波，难度递增

### 基础机制
| 机制 | 说明 |
|------|------|
| 移动 | 4 方向移动（上下左右），速度恒定 |
| 射击 | 单发子弹，默认冷却 500ms |
| 碰撞 | 坦克不可穿过砖块、钢铁、水域 |
| 掩体 | 砖块可被子弹摧毁，钢铁不可摧毁 |
| 水域 | 坦克不可通行，子弹可飞过 |
| 森林 | 坦克可通行，提供视觉隐蔽 |
| 基地 | 被子弹击中即摧毁，游戏结束 |
| 重生 | 死亡后 3 秒重生，附带 3 秒临时护盾 |

### 胜利条件
- 尽可能在更高波次存活
- 击杀得分排名（多人模式）

### 计分规则
| 行为 | 分数 |
|------|------|
| 击杀敌方坦克 | +100 |
| 拾取时间冻结 | +50 |
| 拾取地形编辑器 | +75 |
| 拾取护盾 | +30 |
| 拾取急速射击 | +40 |
| 拾取地雷 | +60 |

## 战术 AI 行为树设计

### 行为树架构

```
Root (Priority Selector)
├─ [优先级 1] 基地威胁检测 → 防御
│   └─ Sequence: 玩家靠近基地? → 向基地移动 + 射击
│
├─ [优先级 2] 道具感知 → 收集
│   └─ Sequence: 附近有道具? → 移向道具
│
├─ [优先级 3] 敌人在射程 → 攻击
│   └─ Sequence: 玩家在 8 格内? → 追击 + 射击
│
└─ [优先级 4] 角色分工行为 (Selector)
    ├─ Flanker (侧翼兵)
    │   └─ 计算侧翼位置 → 移动到玩家侧后方 → 伏击
    │
    ├─ Rusher (突击兵)
    │   └─ 直接冲向基地 → 沿途攻击遇到的玩家
    │
    ├─ Defender (守卫兵)
    │   └─ 在基地周围圆形巡逻 → 攻击靠近的玩家
    │
    └─ Scout (侦察兵)
        └─ 随机探索地图 → 发现玩家后追击
```

### AI 角色协同策略

| 角色 | 战术职责 | 行为特征 |
|------|----------|----------|
| 🔴 **Rusher** 突击兵 | 正面佯攻 | 直线冲向基地，吸引火力，打乱玩家阵型 |
| 🟠 **Flanker** 侧翼兵 | 侧翼包抄 | 绕到玩家侧后方，在掩体后伏击 |
| 🟣 **Defender** 守卫兵 | 基地防御 | 在基地外围巡逻，拦截靠近的玩家 |
| 🟢 **Scout** 侦察兵 | 地图侦察 | 大范围移动，发现玩家后呼叫协同 |

### AI 个体差异
每个 AI 坦克有独立的**性格参数**：
- `aggression`（侵略性 0.3-1.0）：影响追击距离和射击频率
- `caution`（谨慎度 0.3-1.0）：影响躲避子弹概率
- `coordination`（协同度 0.3-1.0）：影响响应基地威胁的速度

### 卡住检测
AI 持续检测位置变化，若 1.5 秒内无位移（卡墙），自动切换方向，模拟"思考"行为。

## 道具系统

### 4 种创新道具

| 道具 | 图标 | 效果 | 持续时间 | 战术价值 |
|------|------|------|----------|----------|
| ⏱️ **时间冻结** | ❄️ | 冻结所有敌人，使其无法移动和射击 | 3 秒 | 紧急逃脱 / 集火秒杀 / 保护基地 |
| 🧱 **地形编辑器** | 🔧 | 在基地四角生成钢铁掩体（不可破坏） | 永久 | 战略布防 / 改变地形 / 堵截敌人路线 |
| 🛡️ **能量护盾** | ✨ | 玩家获得无敌状态（含视觉光环效果） | 8 秒 | 强攻突破 / 掩护队友 / 安全拾取道具 |
| ⚡ **急速射击** | 🔥 | 射速提升至 3 倍（冷却 500ms → 200ms） | 10 秒 | DPS 爆发 / 快速清场 / BOSS 战 |
| 💣 **反坦克地雷** | 💥 | 在玩家身后放置伪装成砖块的地雷 | 永久（触发即毁） | 设伏 / 封锁通道 / 保护退路 |

### 道具生成规则
- 每 **15 秒** 随机生成一个道具
- 地图上最多同时存在 **4 个**道具
- 生成位置随机（避开已有方块区域）
- 道具类型随机分布

## 动态关卡生成算法

### 设计理念
根据**玩家行为档案**动态调整关卡参数，使每局体验不同：
- 激进型玩家 → 更多开放空间 + 更多敌人
- 防守型玩家 → 更多掩体 + 更强敌人
- 机动型玩家 → 更多森林隐蔽 + 复杂通道

### 玩家行为档案
系统持续采集以下指标：
```javascript
behaviorProfile = {
  aggression: 0.0~1.0,  // 射击频率 + 追击距离
  defense:    0.0~1.0,  // 与基地的平均距离
  mobility:   0.0~1.0,  // 移动频率 + 位移量
}
```

### 算法伪代码

```
function generateLevel(behaviorProfiles, wave):
    // 1. 聚合所有玩家行为
    avgAggression = mean(profiles.map(p => p.aggression))
    avgDefense    = mean(profiles.map(p => p.defense))
    avgMobility   = mean(profiles.map(p => p.mobility))
    difficulty    = min(1.0, wave / 10)

    // 2. 砖块密度 = 基础密度 + 难度增量
    //    激进玩家 → 减少砖块（更多开放空间）
    brickDensity  = 0.12 + difficulty * 0.15
    aggressionMod = 1 - avgAggression * 0.3
    totalBricks   = MAP_SIZE * brickDensity * aggressionMod
    bricks        = randomPlace(totalBricks, avoid: baseArea)

    // 3. 钢铁掩体 = 防守型玩家多给
    steelCount    = 8 + avgDefense * 20 + difficulty * 5
    steels        = randomPlace(steelCount, avoid: baseArea)

    // 4. 水域 = 激进型玩家少给（不限制移动）
    waterPatches  = 2 + (1 - avgAggression) * 3 + difficulty
    waters        = clusterPlace(waterPatches)

    // 5. 森林 = 机动型玩家多给（提供战术隐蔽）
    forestClusters = 3 + avgMobility * 5
    forests        = clusterPlace(forestClusters)

    // 6. 高难度额外调整
    if difficulty > 0.5:
        // 在关键通道放置钢铁墙
        placeSteelBarricades(centerColumn)

    return { bricks, steels, waters, forests, basePos }
```

### 关键参数影响表

| 玩家类型 | 砖块密度 | 钢铁数量 | 水域数量 | 森林数量 | 敌人倾向 |
|----------|----------|----------|----------|----------|----------|
| 激进型 (高aggression) | ⬇ -30% | ⬇ 少 | ⬆ 多 | ➡ 标准 | Rusher比例↑ |
| 防守型 (高defense) | ⬆ 标准 | ⬆ 多 | ➡ 标准 | ⬇ 少 | Defender比例↑ |
| 机动型 (高mobility) | ➡ 标准 | ➡ 标准 | ⬇ 少 | ⬆ 多 | Scout比例↑ |

## 网络架构

### 权威服务器模型
```
┌──────────────────────────────────────┐
│            Node.js Server             │
│  ┌────────────┐  ┌────────────────┐  │
│  │ Game State │  │ Level Generator│  │
│  │ (权威状态)  │  │ (动态关卡)     │  │
│  └──────┬─────┘  └───────┬────────┘  │
│         │                │            │
│  ┌──────┴────────────────┴────────┐  │
│  │     WebSocket Server (ws)      │  │
│  └──────┬─────────────────────────┘  │
└─────────┼────────────────────────────┘
          │ 30 tick/s
    ┌─────┼─────┬─────────┐
    ▼     ▼     ▼         ▼
 ┌────┐┌────┐┌────┐   ┌────┐
 │P1  ││P2  ││P3  │...│P4  │
 └────┘└────┘└────┘   └────┘
  Client: Canvas Renderer
```

- **Tick Rate**: 30 FPS（服务端更新频率）
- **协议**: JSON over WebSocket
- **消息类型**: `move`, `shoot`, `chat`, `gameState`, `init`, `newWave`
- **延迟处理**: 客户端预测移动，服务端权威矫正
- **最大玩家数**: 4 人同时在线

| `game.js` | ~260 | 游戏循环、状态同步、HUD更新、特效管理 |

## 技术亮点

1. **权威服务器架构** — 防作弊，所有碰撞判定在服务端
2. **程序化音效** — 使用 Web Audio API 生成 8-bit 风格音效，零外部依赖
3. **像素风渲染** — Canvas `imageSmoothingEnabled = false` + 手绘瓦片纹理
4. **动态波次系统** — 每波敌人数量递增（4 + wave * 2）
5. **零外部资源** — 无图片/音频文件，纯代码驱动
